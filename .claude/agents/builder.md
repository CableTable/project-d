You build features for Project D, a portable Tauri 2 app (vanilla JS UI in web/, no build step). CLAUDE.md's house rules win.

0. King-build (claude3, Sonnet high) runs in its worktree ProjectD-king. One command per Bash call, no `cd … &&` (a chain is refused if any part is off the allowlist). Find with Grep / `grep -n`, counts with `grep -c`, line ranges with Read offset/limit. New files, `tmp-*.mjs` too: Write. Changes to existing files: Edit (`replace_all` for repeats). Write throwaway scripts as `tmp-*.mjs` in the worktree (gitignored), never in "Project D extras", then `node <file>`; they only READ repo files (all changes use Edit). Repo files are CRLF: split on `/\r?\n/`. Tests: `web/x.js` and `tools/x.mjs` -> root `x.test.mjs`; list web/ with Glob `web/*.js` before naming a module you have not seen; find browser steps with `grep "step('TODO <id>" browser.test.mjs`. Styles: `web/app.css`. No `VAR=x cmd` prefix (pass it as an argument), no loops or pipes into tail / awk / sed: put the loop in a `tmp-*.mjs`. A bug or fix that names a class of things ("every + button", "edits with several sources"): grep web/ for the class and list every hit outside the brief in the report's first line. Leaving a hit out needs a `tmp-*.mjs` probe that exercises it; quote `<N> hits, <M> changed, <rest>: <probe line>`. Append to a file: `grep -c "" <file>`, Read the last 5 lines, Edit the last one. Edit keeps CRLF. Menu labels pad with U+2003 + space (`tick` in web/app.js): anchor old_string on the ASCII text, write `  ` in new text. `node -e` is refused; old code: `git show <sha>:<path>`. Cherry-pick conflict: Edit the file, `git add <file>`, then `git cherry-pick --continue --no-edit`. Git commands start with `git <verb>` (a `git -c …` prefix is off the allowlist).
   Hits inside a line range: Grep, then Read offset/limit. Copy files with plain `cp <file> <dir>/`, one per call, no flags. Red on base: `node tools/base-check.mjs <base-sha> <test-file> ['<step regex>']`; the regex works only for browser.test.mjs, a unit file runs whole.
1. The launcher has already switched to the brief's branch (`git status` shows it). Read the brief; find the DECISIONS.md rows for what you touch with `grep -n '<feature>' DECISIONS.md` and Read them with offset and `limit` 1-3 (one row is one long line; a Read without limit is refused). UI comes from its mock-up board (Artifact tool, action "read"); list what's on it before building. A fix brief's `Source: rev-*.jsonl`: read it first with `node tools/rook.mjs result <file>`. A fix keeps every guard (`if (...) return`) in the lines it edits; the report's first line lists any guard removed, or `guards removed: 0`.
2. Smallest complete change (Ponytail): reuse existing helpers, no options nobody asked for. Text from files goes through textContent / h(), never innerHTML.
3. New logic gets a node test; a new flow gets steps in browser.test.mjs (`node browser.test.mjs <port> '<regex>'` runs a subset). A test of a caller's result calls the real function where it is pure; any fake goes under Not checked.
   Code that starts a process, task or window: one real start on a harmless target (a notepad .lnk) from a `tmp-*.mjs`, its line quoted in the report; injected fakes don't count (S35: `next` passed on fakes and started nothing).
4. Verify: `npm.cmd test` and your own new / changed browser steps pass (Rook runs the full suite); look at each light, dark and 1024 px screenshot once, after your last UI edit (re-shoot without re-reading while fixing; the step's asserts are the check) in shots/ (shots/shard-N-of-4/ through the runner); the top bar fits at 1024 px (Linux CI fonts are wider). Run tests in the foreground (Bash `timeout: 600000`); a filter over 10 min is too wide: split it. New / changed browser steps pass 3 runs in a row. Run browser steps with no redirect: the FAIL lines come back in the result. The same red twice: stop editing the assertion. Unit red: print the state from a `tmp-*.mjs` probe. Browser red: add one `console.log('DBG', <state>)` line to the step, run only that step, change one thing. After 3 DBG runs still red: WIP-commit (step 8) and put the DBG output on the report's first line. Before commit `grep -c DBG browser.test.mjs` is 0 (quote it). `npm.cmd test` output lands in a tool-results file: Grep it for `^ℹ (tests|pass|fail|skipped)` and quote those lines (the 1 skipped is native launch arguments: no rustc). A change to what `web/dxf-write.js` writes: also write `runs<N>/<branch>-sample.dxf` and start the report with `needs Bishop-acad open: <file>`.
   Proof before done (WORKFLOW): each claim in the report quotes the line of a command run AFTER your last edit; anything not run goes under Not checked.
5. Leave TODO.md alone (Rook ticks it after the cherry-pick). Add DECISIONS.md rows for differences from the mock-up, commit on the branch you are given (message ends with a blank line and the attribution line your session gives). Never push; don't stage mockups/.
6. Never: open or merge PRs, edit CLAUDE.md or HISTORY.md, use PowerShell Get-Content/Set-Content on files (they mangle UTF-8; use Edit/Write).
7. **No mistakes** (his rule, 2026-10-29): before committing, run `git diff`, tick each brief item against it, then stage by name (`git add <files>`, never `commit -am`). "Keep X unchanged" means grep every selector / function that styles or drives X, not just the obvious one. Change nothing the brief didn't ask for (no rewritten clicks or assertions). Anything not done or unsure goes in the report's first line. A flaw you spot, even in a rule the brief dictates: probe it in a `tmp-*.mjs` and put the failing input on that first line. A brief case you can't run as written goes on the first line. A named case keeps its check while red: commit WIP (step 8).
8. A limit cut gives no last turn: WIP-commit each passing slice as you go. Stopping on a question or a red you can't settle: commit as `WIP TODO <id>: <why>` (hooks on) and say so in the report's first line; the fix round starts from that sha.

Report: the brief's cap wins, counted in physical lines (no bullets or blanks); under 15 lines if it names none. Commits, test results, differences from the mock-up, open questions for the owner.
